Bulkhead

Every container gets its own exit, or nothing gets out

Two settings to set by hand

confirmed

Two Firefox settings close gaps no extension can reach. There is no API for them — set once, by hand, in about:config.

network.proxy.failover_direct set tofalse

Defence in depth. As of Firefox 154 a failed container exit does not fall back to a direct connection for ordinary page loads, but that gating has changed between versions and this is one line to set. If you have a system or PAC proxy configured, a failed exit falls through to that proxy; the exit check catches it.

network.trr.mode set to5

Turns off DNS-over-HTTPS. Sounds backwards, and it isn't: with DoH on, every container resolves names through the same provider over your ordinary connection, which ties your containers straight back together. With it off, each container's own Mullvad server does its lookups.

The trade-off: tabs that aren't going through Bulkhead will use whatever your computer normally uses for lookups. While the Mullvad app is running that is inside the tunnel; while it isn't, that is your internet provider.

Open a new tab → type about:config → accept the warning → paste the name → set the value. Repeat for the second one.

What Bulkhead can't protect you from
  • A system-wide or company proxy catching a failed container. That is what the first setting above is for.
  • All your containers sharing one DNS provider. That is what the second is for.
  • Bulkhead being switched off, crashed or uninstalled. Nothing protects you then.
  • Anything that leaves Firefox entirely: other browsers, apps, your operating system.

There is deliberately no “test for leaks” button: three detectors were built for one, and all three answered the same with the failover pref in either position — a check that can say safe when it cannot tell is worse than no check. What Bulkhead does instead is keep checking. Each container you have set up is tested against am.i.mullvad.net — through that container's own server — about every ten minutes, and about every thirty seconds while something is wrong. Each check is a few seconds apart from the others on purpose, so they cannot be lined up with each other. If traffic comes out anywhere but the server you chose, that container is blocked.

Containers keep cookies and logins apart, so a work tab and a personal tab can be signed in to the same site as two different people. Bulkhead pins each one to its own Mullvad exit and blocks it whenever that exit is not confirmed working. The two rows above cover everything outside a container.

To make one: open a new tab and press and hold the + button, or install Multi-Account Containers.

Protection

    Timezone matching

    A container's exit IP and the timezone its pages report are two halves of one story, and fingerprinting scripts read both — CreepJS's timezone test derives your zone three ways and compares. With matching on, every context that has an exit of its own presents the IANA timezone of that exit: the zone is taken from the killswitch's own verified health probe (which already rides that container's server) and mapped offline through timezone-database tables. No extra request, no geo-IP service, and because a container's traffic is blocked until its exit checks out, the zone is installed before the first page is even allowed to load. Contexts with no exit assigned are never spoofed — a zone your real IP contradicts is a louder signal than an honest one.

    What timezone matching cannot do
    • Service workers. No API exposes a service worker's realm to page JavaScript, so one fingerprinting from a service worker still sees your system zone. The engine warns in the console when a page registers one.
    • Consistency with the rest of your story. A timezone that disagrees with navigator.language, your Accept-Language or your IP's other attributes is itself a signal. Matching fixes the zone↔exit pair, not the whole fingerprint.
    • Country-level precision in big countries. When the exit's city is not in the offline table, the country's primary zone is used and the row says “country-level”. A pin fixes any case the table misses.
    • Anything below JavaScript. privacy.resistFingerprinting forces UTC engine-wide and overrides this feature; if you run RFP, your matched zone has to be UTC to stay consistent.

    The page-realm engine is adapted from the Timezone Lock userscript (MIT), verified against CreepJS's own derivations including its year-1113 “computed location” probe; the popup's Verify button replays those exact derivations against the live page.

    Server list

    Custom exits

    Your own SOCKS5 servers — an SSH tunnel, a server you are trying out. They are held to the same rule as every Mullvad exit: checked by fetching am.i.mullvad.net through the server itself, blocked whenever that check fails or does not travel through it. What no check can tell you is where a foreign exit comes out — “Protected” on one of these means it answered, not that anyone vouched for it.

    A hostname here is looked up by your system resolver on every connection — use an IP address where you can. Credentials are stored in this Firefox profile unencrypted, and go only to the server itself — in the clear, because SOCKS5 offers nothing better. When editing, an empty password box keeps the saved one; clear the username to drop both.
